# Driverless Bicycle · 无人自行车主控固件

> STM32F4 两轮自平衡自行车的**下位机固件**：动量轮平衡 + 舵机转向 + 与工控机通信。

---

## 一、这台车是干什么的

一台**两轮自平衡自行车**的主控固件，跑在 STM32F4 上（168MHz，Keil MDK 工程）。

它负责三件事：**让车不倒、能走、能转** —— 全部是**毫秒级硬实时**控制。

**⚠️ 先分清分工**（这个项目是"上下位机"结构）：

| 谁 | 在哪 | 管什么 |
|---|---|---|
| **本仓库（STM32）** | 车上的主控板 | 实时控制：平衡、驱动、转向、传感器采集 |
| **工控机（上位机）** | 车上的电脑 | 视觉识别、路径规划、决策 —— 通过串口与本板通信 |

**所以"聪明"的部分不在这里** —— 这里只负责"听话地把车控制稳"。

## 二、硬件构成

| 部件 | 接口 | 作用 |
|---|---|---|
| **IMU**（陀螺仪+加速度计） | UART8 | 姿态（roll/pitch/yaw + 三轴角速度） |
| **ODrive 电机驱动** | CAN2 | 两个电机：**动量轮**（平衡用）+ **后轮**（驱动用） |

| **按键** | GPIOE4 | 手动触发 |

## 三、控制架构（这是最该看的部分）

### 3.1 时间片调度（`task.c` → TIM3 中断，2ms 一拍）

**所有控制都在这一个 2ms 中断里按计数器分频**：

| 周期 | 频率 | 做什么 | 为什么这个频率 |
|---|---|---|---|
| **2ms** | 500Hz | 读 IMU + **动量轮**控制 | 平衡的实时性要求最高，慢了必倒 |
| **10ms** | 100Hz | **后轮**控制 | 驱动响应可以慢一点 |
| **20ms** | **50Hz** | `rate_set()`：速度 + 转向 | 人操作/上位机指令的节奏 |
| **40ms** | **25Hz** | `balance()`：平衡串级 PID | PID 不需要跑那么快 |

> 📌 **重要**：中断里只做"取值 + 计算 + 发指令"，**绝不做任何阻塞操作**（发串口用的是非阻塞写法）。

### 3.2 平衡原理：**动量轮（反作用轮）**

这不是"骑手那套"（靠转向把重心拉回来），而是**动量轮**：

```
车身倾斜 imu.rol
   │
   ├─→ X_balance_Control()   角度环：偏离零点多少 → 要多大的角速度
   │                            输出 PWM_X（期望角速度）
   │
   └─→ Angle_Velocity()      角速度环：用 imu.vx 做阻尼
                                输出 PWM_Final
                                 │
                                 ▼
                        动量轮转速指令 (odrive.set_speed0)
                                 │
                                 ▼
                        动量轮转起来 → 反作用力矩 → 车身被"推"回竖直
```

**为什么串级？** 单用角度环会在过零点来回抽；加了角速度环（`imu.vx`）相当于加阻尼，才能稳住。

### 3.3 ⭐ 动态零点自校准（`Auto_Calibrate_Zero`）—— 这个算法值得单独说

**问题**：车的机械零点会变（配重、装配、磨损），如果零点不准，车会一直"偏着走"。

**解法**（思路很巧）：

```
前提：车身近乎竖直（|rol| < 4°）
  ↓
收集 2 秒内（50 个点 @25Hz）的动量轮转速
  ↓
看这 2 秒的【平均转速】：
    如果均值 ≈ 0  → 说明零点是对的（动量轮不用持续出力）✅
    如果均值 > 0   → 说明车偏了，需要持续出力 → 把零点往负方向微调
  ↓
双梯次逼近：
    偏载大（|均值| > 3）  → 每轮调 0.005  （快）
    偏载小（0.5 ~ 3）     → 每轮调 0.001  （慢，精雕）
  ↓
限制在 ±3° 内（防止漂移过大出危险）
```

**效果**：车会**自己"找平"**，把机械偏差慢慢补偿掉。

### 3.4 零点是怎么合成的（`task.c:233`）

```c
param.angular_zero = BASE_ANGLE_ZERO(-2.35)   // 基础物理零点（装配时量的）
                   + (pwm_delta * -0.004)      // 舵机偏转补偿（打舵会改变重心）
                   + Roll_Zero;                // 自动校准值（上面那个算法调的）
```

**三个分量各管一件事**：装配误差 / 舵机动态影响 / 长期漂移。

### 3.5 倒地保护

`|imu.rol| > 8°` → **立刻**停动量轮 + 停后轮 + **清空全部积分项**。

> ⚠️ 清积分很重要：否则车扶正后会带着饱和的积分"暴冲"一下，很危险。

## 四、通信协议

### 4.1 上报给工控机（USART6，每 50ms 一次，`main.c`）

```
R:<roll角度>,Z:<零点校准值>,M:<动量轮RPM>,W:<后轮RPM>\r\n
```

例：`R:-1.23,Z:2.35,M:850,W:120`

### 4.2 IMU 帧（UART8，`packet.c`）

```
0x5A | 0xA5 | 长度(2B) | CRC16(2B) | 数据...
```

用**逐字节状态机**解析（`kStatus_Idle → Cmd → LenLow → LenHigh → CRCLow → CRCHigh → Data`），CRC16-CCITT 校验通过才回调。

### 4.3 上位机/视觉帧（UART7，`upper.c`）

用 `0xA5` 作帧头，带异或校验（见 `back_center_data = {0xa5,0x01,0x01,0x00,0x01^0x01^0x00}` 的"回中"指令）。

## 七、几个值得学的工程细节

1. **舵机 PWM 直接写寄存器**（`servo.c`）
   `htim2.Instance->CCR1 = pulse;` —— 绕开 HAL 的层层封装，保证**最高优先级写入**，PWM 不会抖。

2. **电机转速用"三取平均"滤波**（`odrive.c`）
   `fliter_speed[3]` 环形缓冲，`now_speed = (s[0]+s[1]+s[2]) / 3` —— 简单有效地压 CAN 回传的抖动。

3. **IMU 滤波系数 `alpha = 0.5`**（`imu.c`）
   代码里写得很直白：*"原来的 0.03 会导致约 60ms 的信号延迟，平衡车会因为反应慢而必倒"*。
   **这是一条用血换来的经验** —— 实时系统里，滤波器不能太"重"。

4. **CAN2 的过滤器 Bank 从 14 开始**（`odrive.c`）
   STM32F4 的 CAN1/CAN2 共用过滤器，CAN2 从机必须显式指定 `SlaveStartFilterBank = 14`。
   代码注释写着"核心修复"，说明踩过坑。

5. **速度/转向都做了"柔性斜坡"**（`task.c: rate_set`）
   不直接跳变，而是按 `STEP_SIZE` 逐拍逼近 —— 防止舵机和后轮被指令"打"一下。

## 八、已知局限 / 可改进点

> 记录这些是为了**后面接手的人**（包括我自己）不再踩坑。

1. **`packet.c` 的注释是 GBK 编码** —— 在 UTF-8 环境下显示为乱码（内容其实是正常的中文说明）。
2. **`task.c` 的 `run_flag` 恒为 1** —— `rate_set()` 第一行就置 1，所以那个 `else` 分支（停车复位）**实际走不到**。要做"停车态"得改这里。
3. **`upper.c` 的 `UART7_IRQHandler` 是空实现** —— 视觉数据的接收中断还没写。
4. **PID 参数硬编码在 `param_init()`** —— 没有整定记录，换车/换负载后需要重新调。
5. **上报格式是自定义文本**（`R:..,Z:..`）—— 好处是人能直接读，代价是解析要写对。

## 九、术语速查

| 术语 | 意思 |
|---|---|
| **动量轮 / 反作用轮** | 高速旋转的飞轮，靠改变自身角动量产生反作用力矩，用来平衡 |
| **ODrive** | 开源的高性能电机驱动器，支持 CAN 控制、带编码器闭环 |
| **串级 PID** | 两个 PID 嵌套（外环角度 → 内环角速度），比单环更稳 |
| **零点（angular_zero）** | 车"真正竖直"时 IMU 的读数，平衡控制的目标值 |
| **倒地保护** | 倾角过大时切断出力，防止失控 |
| **前视/循迹** | 视觉模块算出车相对路径的偏差，回传给本板用于转向 |
